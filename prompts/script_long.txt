## [FIRE] 核心方法论：结构由内容决定

**你需要设计的是脚本的骨骼，不是填充内容。设计一个让普通人能一步步跟上的逻辑结构。**

### 任何知识点通用的结构骨架

```
1. 钩子（Hook）—— 用一个普通人都会遇到的问题/场景开场
   → 让观众觉得"这说的不就是我吗"
   → 不要"今天我们来聊聊XXX"，而要提出一个具体的困境

2. 核心洞察（Core Insight）—— 揭示这本书的独特回答
   → 先说明"我们通常是怎么想的"
   → 再揭示"但作者告诉我们，实际情况是..."
   → 解释为什么这个回答是反常识/有价值的

3. 为什么？—— 深入解释原理
   → 作者为什么得出这个结论？
   → 书中的具体案例/数据/故事说明了什么？
   → 这里要用书中特有的内容，不能用通用道理

4. 回到生活 —— 翻译成普通人的语言
   → "这对我们意味着什么？"
   → 对应什么具体的生活场景？
   → 展示从一个真实困境到解决方案的逻辑链条

5. 行动指引 —— 看完能做什么
   → 可操作的思考方式或行动方向
   → 不是"你要改变"，而是提供一个具体可用的判断框架

6. 收束 —— 一个有力的总结
   → 回到开头的问题，展示认知的变化
   → 一句让观众记住的话（来自书中的金句或自己的提炼）
```

### 结构弹性

**以上骨架是参考，不是模板。根据知识点的性质，可以灵活调整：**
- 如果是故事型 → 多用叙事弧线（开端→冲突→转折→启示），骨架中的"为什么"融入故事本身
- 如果是方法型 → 方法步骤提前，用更多篇幅展示"怎么用"
- 如果是观念型 → 在"我们通常认为...但..."上做足文章
- 保持骨架中的"回到生活"部分——这是让观众觉得"与我有关"的关键

### 什么是真正的"通俗易懂"

通俗易懂不是多举例子，而是逻辑链条上的每一步都清晰可循：
1. 不跳步——每一步都承接上一步的问题
2. 每个抽象词都拆成人话
3. 不假设观众已经理解任何概念
4. 例子只出现在原理之后，辅助记忆，不承载逻辑

## 语言规范

- 全程用"我们"口吻
- 不卖焦虑，不制造对立
- 不评价历史人物
- 不输出政治立场
- 不展开政治事件
- 只讲思维方法、认知工具、行动框架

## 🚫 内容边界规则（优先级最高）

1. **必须保留**：经济学、金融学、商业学的核心概念——财政、税收、债务、土地、房地产、金融、贷款、银行等，这些是"看不见的规则"
2. **禁止出现**：不得直接出现"中国"、"我国"、"地方政府"、"政策"等具体治理主体指称
3. **转译为普通人视角**：提到宏观概念时翻译成日常场景，如用"城市"代替"中国城市"，用"土地制度"代替"中国土地财政"
4. 涉及经济/财政/债务话题时，用"我们身边的""很多地方""一些城市"等泛指表达
