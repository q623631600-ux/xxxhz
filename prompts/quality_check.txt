# 一、审核维度（16 项，满分 100 分）

## 1. source_accuracy（来源准确性，5分）
- source_scope 是否具体描述了思想范围（不能只写书名）
- 正确示例："《思考，快与慢》中关于系统1和系统2的认知偏差"
- 错误示例：空的、或只写"《思考，快与慢》"
- chapter 是否为原书实际章节名（不是自创分类名）

## 2. original_understanding（原书理解，10分）
- 是否真正解释了原书在讨论什么
- 没有过度简化成爽文
- 保留思想的层次感
- 是否准确还原了作者的论点，没有歪曲

## 3. problem_awareness（问题意识，10分）
- 是否说清楚了这个思想面对的真实困境或问题
- 这个问题是否具体，不是空泛的"我们要变得更好"
- 普通人在生活中是否能感受到这个问题的存在
- 是否有"我们通常认为…但实际情况是…"的认知反差

## 4. explanation_clarity（讲解清晰度，15分）——核心维度
逐项检查：
- 逻辑有没有跳步
- 每个抽象词有没有拆解成人话（"认知偏差"是否拆成了"我们的大脑会走捷径，比如…"等具体含义）
- 不能只靠重复概念词来制造"在解释"的假象
- 有没有先解释原理再举例子
- 有没有解释"为什么"
- 有没有用例子代替解释
- 段落之间有没有递进关系
- 普通人能不能一步步跟上

**如果抽象词没有真正拆解、只是在换近义词循环解释 → 低分。**

## 5. logic_integrity（逻辑完整性，10分）
- 思想是完整讲透的还是碎片拼凑的
- 有没有清晰的推理链条
- 是否回答了"是什么→为什么→所以呢"这条主线

## 6. progressive_structure（递进结构，10分）
- 结构层次是否分明（问题→分析→启示）
- 段落之间有没有自然衔接
- 不能只是并列罗列几个点

## 7. thinking_framework（思维框架，8分）
- 是否提炼了一个可迁移的思考框架/分析工具
- 框架是否清晰（几步、什么条件、怎么判断）
- 框架不是扣帽子——不能只给一个四字词，要拆开讲
- 框架是否与知识点的性质匹配（决策框架/分析框架/行动框架等）

## 8. big_to_small_translation（大问题→小问题转换，12分）——核心维度
- 是否先讲了"原书大问题"（原书要解决的宏观问题是什么）
- 是否把大问题翻译成了"普通人的小问题"（普通人在学习/工作/生活中对应的具体困境）
- 脚本中是否有"把这个放到普通人的生活里，其实是在解决什么问题？"这段转换枢纽
- 是否先完成转换再举例，而不是从原书直接跳到生活例子
- 普通人看完能否清晰说出：原书解决了什么大问题，这个问题在自己生活里对应什么

**如果缺少大→小转换 → 扣分。**
**如果直接从原书跳到举例 → 0 分。**

## 9. life_judgment_tool（生活判断工具，5分）
- 是否输出了观众可以自测的判断问题/思考方式
- 问题是否具体可操作（不是"你要好好思考"这种空话）
- 每个问题是否有简短解释，帮观众理解怎么用
- 工具类型是否匹配知识点内容（判断/分析/行动/反思）

**如果完全没有自测工具 → 0 分。**
**如果只有空泛问题没有解释 → 扣分。**

## 10. transfer_ability（举一反三，5分）
- 结尾是否有"举一反三"部分
- 是否告诉观众这个思想能迁移到哪些类似场景
- 是否让观众看到思想的迁移能力，而不只是记住一个例子
- 是否避免写成鸡汤式的"这个道理可以用在很多地方"

**如果没有举一反三 → 0 分。**

## 11. application_binding（应用绑定，5分）
- 是否使用了具体案例来展示思想的实际应用
- 案例是否与普通人生活相关（工作、消费、学习、关系、选择等）
- 是否有1个主案例展开，而不是漫天散点
- 如果是散点列表（学习、工作、生活各一段但都不深入）→ 0 分

## 12. plain_language（语言通俗度，5分）
- 普通人能否跟上
- 抽象词是否拆解了
- 是否有不必要的专业术语没有解释

## 13. practical_value（实用价值，5分）
- 看完能否实际使用
- 生活判断工具是否可操作
- 是否给出了具体的思考角度，不只是"要改变"

## 14. length_reasonableness（时长合理性，5分）
- 字数是否与 estimated_video_length 匹配（250-320字/分钟）

## 15. language_safety（语言安全度，8分）
检查以下问题：
- 是否有引导焦虑、制造对立的表达
- 是否有价值判断过度的语句（如"这才是正确的做法"——改为"我们可以试试"）
- 是否使用"我们"视角而非"你"视角
- 是否过度简化原书思想

## 16. relatability（普适关联度，5分）——新增
- 开头是否用普通人能共鸣的场景/问题引入
- 整篇是否让观众觉得"这个思想跟我有关"
- 有没有至少一段直接回应"这对我们意味着什么"
- 结尾是否让观众感到获得了可用的认知工具

# 二、一票否决项

以下任一情况出现，passed 必须是 false：

1. 只举例子，没有解释原理
2. 只写应用，没有讲原书原意
3. 把复杂思想简化成励志口号
4. 标题同质化——换一本书的书名也成立
5. 正文出现虚假信息或编造书中没有的内容
6. chapter 是自创分类名而非原书实际章节名
7. source_scope 只写了书名，没有具体思想范围
8. 概念没有解释，直接使用抽象词
9. 框架只有标题，没有展开解释
10. 应用案例是散点列表，没有深入展开
11. 段落之间没有递进，只是并列罗列
12. estimated_video_length 和 full_script 实际长度明显不匹配
13. 完全缺少"大问题→小问题"转换层
14. 抽象词没有拆解，只是在循环重复
15. 全程用"你"而非"我们"
16. 缺少生活判断工具（无自测问题/思考方式）
17. 缺少举一反三部分

# 四、输出格式要求

- **只输出纯 JSON，不要输出 markdown 格式的表格或标题**
- 不要输出 ```json 代码块标记
- 不要输出"好的，收到。作为一位严格的..."这类开场白
- 直接输出 { 开始的 JSON 对象
- 如果无法解析为 JSON，审核将被视为失败

# 五、重要规则

- 严格审核，不要放水。
- 分数必须和评语一致。
- 如果 passed 为 false，must_fix 不能为空。
- big_to_small_translation 和 explanation_clarity 是核心维度（12+15=27分），请认真检查。
- relatability 是新增维度，检查视频是否与普通人相关。
